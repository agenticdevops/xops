# POC Plan — Full Spine, One Slice

**Goal:** Telegram message → goose recipe run (k8s skill, guarded, scoped) → verify actual cluster state → verified reply.
**Demo:** seed broken deployment in kind `troublesim` → message bot → watch fix + verified reply.
**Status:** in progress. TDD hybrid: pure logic (recipe gen, output parse, guard decisions) test-first; subprocess/cluster paths manually verified (spike exception).

## Reference patterns (read, reuse, adapt)

- Invocation (openagentix `bench/run-bench.sh:99`):
  `cd $WD && HOME=$FAKEHOME GOOSE_MODE=auto goose run --recipe r.yaml --params namespace=$NS --no-session --output-format stream-json --quiet --max-turns 20`
- Skills live in `$WD/.goose/skills/` (workdir-local); watchdog must kill process *children* first (goose survives TERM)
- Recipe template: `openagentix/recipes/fix-workload-slim.yaml` (load_skill convention)
- Skill to port: `openagentix/skills/k8s-pod-restart-triage/` (+ `_shared`)
- Verify: `openagentix/bench/verify.sh` pattern — pass/fail from cluster state only
- Seed/teardown for demo: `openagentix/bench/seed.sh`, `teardown.sh`
- Guard: aoh fail-closed verb allowlist idea → POC = kubectl PATH-shim; allowed verbs from skill Safety section (get, describe, logs, patch, set, rollout, scale)
- goose provider already configured on machine: claude-acp

## Tasks

1. **Engine module** `packages/gateway/src/engine/` (POC-local types; promote to core post-gate)
   - `recipe.ts` — generate recipe YAML from skill name + params (template literal, no yaml dep if avoidable) [TDD]
   - `goose.ts` — spawn goose subprocess (workdir prep, skills copy, stream-json capture, watchdog kill-children-first) [manual]
   - `parse.ts` — extract final result/text from stream-json output [TDD]
2. **Guard** `packages/gateway/src/engine/guard/`
   - `kubectl` shim script prepended to PATH of goose run: fail-closed verb allowlist + namespace pinning; log every call [TDD decision fn, shell wrapper thin]
   - scoped kubeconfig: `scripts/provision-poc-rbac.sh` — namespace-bound SA on troublesim, generates kubeconfig file [manual]
3. **Verify** `packages/gateway/src/engine/verify.ts`
   - post-run: re-run skill diagnose.sh, assert pods Ready + restarts stable; attach verdict to result [manual + unit for verdict logic]
4. **Wire Telegram** — `server.ts`: route incident-ish messages to engine instead of `AIRuntime` (AIRuntime untouched during POC); reply = result + verification verdict
5. **Demo runbook** `scripts/poc-demo.sh` — seed broken workload → point at bot → cleanup

## Kill signals (abandon fast if hit)

- goose subprocess flaky (hangs, unparseable output) after honest debugging
- guard breaks goose loop (can't act at all fail-closed)
- chat-unusable latency (>3–4 min per simple fix)

## Gate review after demo

Repeatable? Solid? Latency OK? Would use on real cluster? → go/no-go per ROADMAP.md.
